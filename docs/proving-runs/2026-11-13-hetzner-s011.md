# Proving run: S-011 host requirements and S-014 volumes

| | |
| --- | --- |
| **Date** | 2026-11-13 |
| **Scope** | S-011 and S-014 end to end: a `LoggingStack` on two hosts that `cloudfall logging deploy` provides everything for (secrets, CA and certificates, the gateway port, the gateway name, package pins, data volumes), then audit |
| **Hosts** | Two Hetzner Cloud cx23 (fsn1), stock Debian 13.6 images, two 30 GB volumes on the backend; all deleted after the run |
| **Code** | The tip of #253 (S-011 slices through #238, S-014 #248, #249, #253) |
| **Verdict** | Every provider met its requirement on real hosts on the first run; a second deploy changed nothing; audit was compliant for every requirement check and reported an unmounted volume as drift |

## Method

Two disposable cx23 hosts were created from the stock `debian-13` image with a throwaway
ed25519 key: a **backend**, which was also a collector, and a separate **collector**. Two
30 GB volumes were attached to the backend and made into `vg_data` by hand (`pvcreate`,
`vgcreate`), the install step S-014 leaves to a person.

A dedicated project declared both servers with their IPv4 and IPv6 network, a `Baseline`
with a default-deny firewall that opens nothing beyond SSH and one storage pool (`vg_data`,
`primary` and `secondary` on the two volumes), and a `LoggingStack` with `migration.mode:
none`, Loki 3.7.7, Grafana 13.2.1, Alloy 1.19.2-1, a webhook receiver and an SMTP receiver
whose password file Cloudfall had to provide. Secrets were kept with sops and a throwaway age
key. No file was put on either host by hand.

Only public entry points were used: `config validate`, `logging deploy` (plan, then `--yes`
twice), `secrets input`, `observe`, `audit`.

Logs and `node_*` metrics from both hosts reached Loki and Prometheus, labelled by `server` |

## Findings

- The collector audited as firewall drift: `logging.yml` enforces the firewall on the backend
  only, and `baseline` was not run on the collector in this run. Not an S-011 defect; a host
  needs its baseline converged for its firewall
- The first `--yes` attempt stopped at its precondition because the CLI was started by path
  with its virtual environment off `PATH`, so `ansible-playbook` was not found. Nothing had
  changed; it is how the run was started, not the code

## Caveats

- One run, one Debian release, Hetzner Cloud block volumes rather than NVMe partitions
- Not exercised live: raid1 volumes (S-014-6), the refusals (S-014-7), growing a volume,
  renewing a certificate, input off a terminal; each is covered by unit tests only
