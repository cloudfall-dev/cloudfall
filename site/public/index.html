For agencies and MSPs

Hand the routine to an agent. Keep the rules and the record.

Disks filling up, certificates expiring, backups nobody has tested. Your agent takes the routine across client servers, but only through operations you allow. Each one has a risk level, a verify step and a record. An operation you haven't declared doesn't exist to the agent.

No baseline yet? Start from Cloudfall's operations for hardening, PostgreSQL, backups and deploys. Already on Ansible? Declare the playbooks you run, as on the right. No import, no second copy of anyone's fleet.

operations/deploy.ymlon Ansible
id: deploy
playbook: playbooks/deploy.yml   # your existing playbook
risk: mutating                   # read | mutating | destructive
targets: component
inputs:
  version: string
preconditions:
  - health: ok
verify:
  playbook: playbooks/health.yml
readRuns freelyFacts, health, inventory. Nothing to gate.
mutatingCheck mode, then approvalThe diff is recorded first and a person approves it. Once your policy licenses the class, the next identical failure gets fixed alone.
destructiveAlways a humanData deletion, DNS cutover, promotion. No policy and no prompt can unlock it.

After an incident

The record is the page you send your client

Your client doesn't want an Ansible log. They want to know what happened, who allowed it and whether it worked. Every sentence below comes from a field of the record.

Under the hood

The gate lives in Cloudfall, not in the prompt

An agent can be talked out of a rule in its instructions. It can't be talked out of a process that refuses to run a destructive operation without a person.

  1. Observe snapshots
  2. Decide operation, targets, why
  3. Preview check mode, diff
  4. Approve gate by risk
  5. Run through Ansible
  6. Verify update snapshots
  • Tool listGenerated from your declared operations. Risk levels go out as MCP tool annotations, so any client can gate on them too.
  • StatusDerived from validated observations, never from the agent saying so. cloudfall audit reports drift with distinct exit codes.
  • Your agentClaude Code, Codex or any MCP client. cloudfall init writes an AGENTS.md: every command sorted by effect and the gate it needs. Your agent reads it first.
  • Same surfaceOne CLI and one MCP server, the same commands for people and agents, JSON everywhere.
  • Exit planPlain systemd, nginx and PostgreSQL on Debian. Remove Cloudfall and any Linux admin can carry on.
