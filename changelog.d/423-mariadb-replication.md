### Added

- A MariaDB service converges its `replication` between two Cloudfall servers. Both servers write a row-based binary log with GTIDs in strict mode, kept seven days, and get their server certificate from the project CA. A primary listens on `listenAddress` too and holds one `cloudfall_repl` account at the IPv4 of each replica's server, requiring TLS, set from the hash of its password, which `cloudfall secrets generate` makes and keeps sops-encrypted: the primary receives only the hash, a replica the password in a 0600 file for the run only, and its firewall admits the port from those addresses only. An empty replica that never replicated is seeded from one consistent dump of its primary at a recorded GTID position, then follows it by GTID over TLS verified against the project CA, read-only, and the converge waits until it reached the primary's position and holds the same tables; a second converge changes nothing. A replica that holds data attaches from its own position only when its primary saw every GTID it holds; otherwise, and when it has no GTID history, the converge stops and drops nothing. Changing a replica to `role: primary` promotes it when its source can't be reached, or is read-only and applied, and the answer names the last GTID it applied; over a running, writable source it stops with `PRECONDITION` naming both positions, and the replica still replicates. Swapping the roles of a pair in one change ends within two converges, with no seed. A replica of a source Cloudfall does not manage is still refused by the role. The primary's replication password is no longer a host requirement at `/etc/mysql/cloudfall/replication-password`: no host keeps it (#423)
