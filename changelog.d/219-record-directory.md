### Changed

- Receipts and operator proposals now land in the project's committed `record/` directory instead of the git-ignored `tmp/`, so the audit trail survives losing the management host (D-16): the defaults of `--deployments`, `--releases`, `--backups`, `--data-migrations`, `--env-receipts` and `--proposals` (on every command and on `cloudfall mcp serve`) are `record/deployments`, `record/releases`, `record/backups`, `record/data-migrations`, `record/env-receipts` and `record/operator/proposals`. `tmp/` keeps only what can be rebuilt: observations, rendered inventory, built artifacts, rendered environment files and the migration plan. A path you pass explicitly keeps working as before. `cloudfall config upgrade` now also moves an existing project's receipts and proposals from `tmp/` into `record/`, listing each move in `upgraded` with its `moved_from`; it drops a file whose identical copy is already in `record/`, refuses with `CONFLICT` and code `upgrade_target_exists`, naming both paths and moving nothing, when a different file is, and a second run changes nothing. Until it runs, `operator list`, `audit`, `services status` and the operator's autonomy pass don't see the receipts left under `tmp/`, so run `cloudfall config upgrade` once after upgrading, then commit `record/`. `cloudfall init` writes the new layout into the project's README, `AGENTS.md` and `.gitignore`, and the operator guide says how to copy `record/` off a management host with no git remote (#219)
- A release receipt no longer holds its release command's output: the command is the application's and may print a secret, and the receipt is now committed. The last 2000 characters stay in `tmp/output/releases/<component>.<release>.log` (`0600`), and `spec.releaseCommand` names that file and its SHA-256 under `output` (`path`, `sha256`) instead of `outputTail`. The `ReleaseReceipt` schema stays `cloudfall/v1`: `outputTail` becomes optional, so receipts written before still validate, and a receipt may not hold both. `cloudfall config upgrade` moves the tail of an old receipt, under `tmp/` or already in `record/`, out to that file the same way, refusing to replace a different file there. A reader of `releaseCommand.outputTail` reads the named file instead, which is gone on another host or once `tmp/` is cleared (#219)
