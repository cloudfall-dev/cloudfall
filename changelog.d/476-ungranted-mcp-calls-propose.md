### Breaking

- Over `cloudfall mcp serve` in a project, a confirmed call of `deploy`, `rollback`, `restart`, `migrate`, `data_copy` or `domains_apply` (`yes: true`), or of `converge_baseline`, `converge_services` or `converge_domains` (`confirm_destructive: true`), now runs only when an `OperatorPolicy` grant covers it in every environment the run touches. Any other confirmed call runs nothing: it answers `PRECONDITION` with `error.context.code: operator_approval_required`, `context.proposal` (the id of a `proposed` agent record it left in the proposal store, `record/operator/proposals/` by default), `context.command` (`cloudfall operator approve <id>`, which a person runs at a terminal) and `context.reasons` (one line per environment, naming why no grant covers it). The same call made again while that proposal is `proposed`, against the same plan, commit and uncommitted changes, returns the same id and writes nothing. A run that changes no declared server, such as a `migrate` whose pending steps are builds and controller steps like `ttl-lower`, touches no environment whose grant could cover it, so it always proposes: its record's `operation.servers` and `operation.environments` are empty (the `OperatorProposal` schema now accepts empty lists there) and its reason says only a person approves it. A `converge_*` call that refuses itself before any playbook, such as `converge_domains` for an undeclared Domain, still refuses as before and writes no record. With no `OperatorPolicy` declared every confirmed call proposes; to keep the one-call flow in an environment, declare an `OperatorPolicy` for it whose `spec.autonomy.operations` grants those classes (`deploy`, `rollback`, `restart`, `migrate`, `data-copy`, `domains-apply`, `converge-baseline`, `converge-services`, `converge-domains`) and earn its `requiredVerifiedRuns`. The checks that came first still do and write no record: argument and config validation, S-008's `deployment_approval_missing`, and a component lock another run holds. The server's instructions say so, and the plan's `approval.selfConfirm` tells an agent in advance. The CLI is unchanged: `cloudfall deploy --yes` in a shell runs as before, and a repository's server lists the same tools (#476)
