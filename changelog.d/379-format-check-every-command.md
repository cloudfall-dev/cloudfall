### Changed

- Every command that reads a project now checks its `[tool.cloudfall] format` first, as `cloudfall config validate` already did: `cloudfall audit`, `deploy`, `add`, `health` and the rest, `cloudfall mcp serve` once at start, and `cloudfall-engine inventory render` and `artifact build`. A project written by a newer Cloudfall, one below the formats this release reads, or one with a malformed format stops the command with exit `PROJECT_FORMAT_UNSUPPORTED` (95, now on `cloudfall-engine` too) before the project is validated, before anything is written under its `tmp/` and before any Ansible run, and `cloudfall mcp serve` refuses to serve it. A format 0 project (no `[tool.cloudfall]` table, or no `pyproject.toml`) still runs every command, each now answering with one `PROJECT_FORMAT_OLD` warning naming `cloudfall config upgrade`. `cloudfall init`, `changelog`, `--schema` and `cloudfall-engine manifest` read no project and run whatever its format (#379)
