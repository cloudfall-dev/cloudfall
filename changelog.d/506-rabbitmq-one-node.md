### Added

- `services.yml` converges a RabbitMQ service of one node with no `clientAccess` (S-023) through the new `cloudfall_rabbitmq` role: `rabbitmq-server` at the declared `X.Y.Z-1` from Team RabbitMQ's repository and the Erlang of the Debian release, all held; the data directory on a `rabbitmq` volume (20 GB, mirrored for one node) that the converge decides with the other volumes; the Erlang cookie Cloudfall generates (`cloudfall secrets generate`) at `/var/lib/rabbitmq/.erlang.cookie`, `0400`; managed settings in `/etc/rabbitmq/conf.d/9*-cloudfall-*.conf` (clients, the inter-node port, epmd and metrics on loopback only, `vm_memory_high_watermark.absolute` from `memoryHighWatermarkMb`, `disk_free_limit` of 2 GB, the node list, continuous membership reconciliation of quorum queues toward three members) and `enabled_plugins` naming the Prometheus plugin alone. The role refuses, before it changes the host, a watermark above six tenths of the server's memory, a hostname that is not the declared one, and a change of the installed version; it refuses an Erlang older than the series needs, and a cluster of three or `clientAccess`, which come later. On the service's server it creates each virtual host with `quorum` as its default queue type, gives its owner every permission there and none elsewhere, and sets the owner's password as RabbitMQ's salted SHA-256 hash, computed on the controller with the salt the user already has, so the password never reaches a node and a second converge changes nothing; `guest` is removed, and `/` while it holds no queue. A virtual host Cloudfall made that is no longer declared is kept with its queues, and its owner's password cleared; `inspect` reads the cluster's virtual hosts and users, and `audit` lists those as undeclared and anything Cloudfall did not make as unmanaged (#506)

### Fixed

- `services.yml` refuses a server that declares a service of a kind it has no role for, instead of converging it as a silent no-op (#506)
- `backup.yml` runs a service's backup on its declared server alone, so a service rendered on several nodes no longer fails the one-server check, and knows the RabbitMQ kind (#506)
- `config validate` compares the nodes of a RabbitMQ service by short hostname, the name RabbitMQ gives a node, so `h2.a` and `h2.b` are refused with `service_rabbitmq_hostname` (#506)
