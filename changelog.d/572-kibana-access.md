### Added

- Who may work in Kibana (S-024): the `cloudfall_kibana` role keeps two roles through Kibana's own role API once Kibana is available, `cloudfall-kibana-view` (Kibana's base privilege `read`) and `cloudfall-kibana-edit` (base `all`), on every space and with no privilege in Elasticsearch, reading each first so an unchanged role is not put again. The S-012 user converge gives each user the Kibana service names in `kibana.users` the role of its `access` next to its own role, which stays unchanged, and takes it away when the user's line is removed; a user `kibana.users` does not name keeps its own role alone. Giving or taking Kibana access sends no password hash, so a password the person changed in Kibana stays until the stored one changes. Every task that reads or writes a role or a user is `no_log` (#572)
