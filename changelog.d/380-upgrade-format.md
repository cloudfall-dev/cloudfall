### Changed

- `cloudfall config upgrade` brings a project to the current format: it runs each rewrite from the project's `[tool.cloudfall] format` to the current one (the step from format 0 is the rename of `ServerType`, `server-types/` and `serverType` and the move of receipts and proposals into `record/`), then writes `format = 1` into the project's `pyproject.toml`, creating the table, or the file, and keeping every other byte of it. A format 0 project with nothing to rename now answers `effect: updated`, since its format is written; a project already at the current format is a noop. The answer gains `from_format` and `format`. It runs on a project too old for every other command, refuses one written by a newer Cloudfall (`project_format_too_new`) or with an unreadable format (`project_format_invalid`) with exit `PROJECT_FORMAT_UNSUPPORTED` (95) and nothing changed, and refuses with `CONFLICT` and code `upgrade_format_unwritable` a `pyproject.toml` whose `tool.cloudfall` is an inline table or dotted keys (#380)
