### Added

- `cloudfall data copy`, and the `data:<database>` step of `cloudfall migrate`, run a preflight on the target host after the empty-target check and before `pg_dump`: it reads both catalogs and refuses a copy the target can't hold, with nothing dumped, the target untouched and no receipt, exiting `PRECONDITION` with code `data_copy_preflight_refused` and four lists in the error context, each item named: `missingSchemas` (a named schema the source lacks), `extensions` (one the selected schemas need, through `pg_depend` or by living in them, or every source extension but `plpgsql` without `--source-schema`, that the target's `pg_available_extensions` lacks), `roles` (a role a row-level security policy on a selected table names that the target's `pg_roles` lacks) and `authReferences` (a function or policy of the selected schemas that references `auth.` when `auth` isn't copied). The role writes the findings to `<service>-<database>.preflight.json` under `--data-migrations`, so the lists arrive whole. With `--source-schema`, `pg_dump` also gets one `--extension` per extension the schemas need (pg_dump 14 or later), and `pg_restore` now runs with `--single-transaction`, so a failed restore rolls back whole, writes no receipt, exits `ENGINE_STEP_FAILED`, and the next run passes the empty-target check (#125)
