### Fixed

- A MariaDB replica declared `primary` whose link's source is no declared service is no longer promoted over a source the controller merely can't see: the role reads the replica's own `Last_IO_Errno` first and refuses with `PRECONDITION` when its last error came from a running source (access denied, a TLS failure), and the controller's probe of the source's port now tells a refused connection from a timeout, no route or a name it can't resolve. Only a refused connection promotes; the others leave the source unknown and refuse with `PRECONDITION`, naming what the controller couldn't read. A link whose `server_id` matches no declared service is matched by its host and port whatever `server_id` it reports, as the code already did, and the comments now say so (#446)
