### Added

- `cloudfall domains apply` renders a Domain's `spec.routes`: a proxy route becomes a `location` that proxies to its `upstream` with the full request path, and a static route serves `<installRoot>/current/<directory>` of its component, answering `spaFallback` for an unknown path when it declares one and 404 when it doesn't. Without a `/` route, a path no route matches answers 404, not Nginx's default page. Locations render longest path first, whatever the declared order, where the single proxy location rendered before (the port 80 server without active TLS, the 443 server with it); the port 80 redirect and the ACME challenge location stay. The site role grants the Nginx worker (`www-data`) traverse-only access (POSIX ACL `user:www-data:--x`, installing `acl`) from the application root to the install root and its `releases/`, so it reads the release files but never `shared/env/<component>.env`, and a deploy or `cloudfall rollback` switches what a static route serves without re-running the domains playbook or reloading Nginx. The domains playbook's early check now refuses only a Domain with neither `proxy.upstream` nor `routes`. A Domain with only `proxy.upstream` renders a byte-identical vhost (#162)
