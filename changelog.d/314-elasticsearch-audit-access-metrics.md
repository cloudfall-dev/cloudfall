### Added

- An Elasticsearch service (S-012) is audited, opened by `remoteAccess`, and scraped for metrics. `cloudfall audit` reports drift on each node when the installed `elasticsearch` package differs from `version`, when `elasticsearch.service` is not running and enabled, and when the managed settings of `elasticsearch.yml` (`network.host`, `http.port`, `http.host`, `xpack.security.enabled`, `xpack.security.http.ssl.enabled`) differ from what the role writes, so a hand edit is drift before the node restarts with it; it reports the node as running an unsupported version once its line is past Elastic's End of Maintenance date at the observation's time (D-12). `inspect` reads `elasticsearch.yml` as text on a server with an Elasticsearch service (`spec.elasticsearch` of the observation). With `remoteAccess`, the firewall opens `bind.port` to `allowedSources` only, HTTP listens on loopback and `listenAddress` and is TLS-only on both, with the node's one certificate from the project CA (the `elasticsearch-transport` certificate requirement of the new usage `server-and-client`, for the server's hostname and every address, the listen address included, at `/etc/elasticsearch/certs/transport.crt`, `transport.key` and `ca.crt`), which the role checks before writing a configuration that names it, and stops on while nothing issues it yet; the role's own API calls then go over HTTPS to the listen address, verifying the project CA. With `metrics.enabled`, the collector renders one Alloy `prometheus.exporter.elasticsearch` for the local node, as the `cloudfall` account, labelled with the service id; Alloy reads the password, and with `remoteAccess` the project CA, as systemd credentials (`LoadCredential`), and `logging deploy` stops before changing the collector when the node's files are not there yet (#314)
