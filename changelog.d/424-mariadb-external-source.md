### Added

- A MariaDB replica declared with `replication.source`, a server Cloudfall does not manage, converges. Before anything is installed on its server, the role logs in to the source with the login `credentialsRef` names, over TLS verified against `caCertificateFile` when declared, through a client module of its own (no `mariadb` client is needed yet), and stops with `PRECONDITION service_mariadb_source_unfit` when the source is not MariaDB, writes no binary log, writes one that is not row-based, runs a release newer than `version`, has the replica's `server_id`, or its account lacks a right `cloudfall_repl` holds; it sends the source `SELECT` and `SHOW` only. An empty replica is seeded from one consistent dump of the source's databases without its users, follows it by GTID, read-only, and ignores `mysql.%` (`replicate_wild_ignore_table`), so a user created or granted on the source afterwards is not applied. The login is staged 0600 on the controller and reaches the replica's server for the run only; the rendered inventory names the source's host, port and whether it uses TLS, never its login. After a promotion, a declared `owner` database the server holds is adopted with its rows (#424)
