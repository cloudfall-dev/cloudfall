### Added

- `services` converges a standalone MariaDB service (S-019) with the new `cloudfall_mariadb` role: it refuses, before any task changes the host, an `innodbBufferPoolMb` above three quarters of the server's memory, a series MariaDB publishes no package of for the server's Debian release, and a series other than the installed one; it mounts the data directory on the mirrored `mariadb` volume the services converge decides with the Elasticsearch volumes, installs `mariadb-server` at the exact declared release from MariaDB's archive and holds it, and writes the managed settings to `/etc/mysql/mariadb.conf.d/90-cloudfall.cnf` (listener on `bind.address` only, buffer pool, `utf8mb4`; no binary log). An `application` database gets a user named after the application's Linux user that logs in through the unix socket only; an `owner` database gets a user whose password reaches the host only as the hash its plugin stores (`mysql_native_password`, or `ed25519` with `authentication: ed25519`), computed on the controller and set only when it differs from the stored one, so a second converge changes nothing. Each user has every privilege on its own database. A user Cloudfall made that is no longer declared is locked, its database left with its rows, and users and databases made by hand are left alone; `cloudfall audit` lists both kinds as undeclared and unmanaged. A `passwordRef` whose file or key is missing stops the converge with `PRECONDITION` before any playbook runs. `remoteAccess` and `replication` are still refused by the role until their own issues land (#420)
