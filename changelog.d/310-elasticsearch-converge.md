### Added

- `services.yml` converges a one-node `serviceKind: elasticsearch` service on Debian 13 through the new `cloudfall_elasticsearch` role (S-012). Its first task refuses a `heapMb` above half of the host's memory before anything changes. It installs `elasticsearch=X.Y.Z` from Elastic's APT repository for the declared major and holds it, and writes `elasticsearch.yml` (`cluster.name`, `node.name`, HTTP on the loopback `bind` only, `bootstrap.memory_lock: true`, security on, never `discovery.type`), a `jvm.options.d` heap file and a unit drop-in with `LimitMEMLOCK=infinity`, all before the package, so its security auto-configuration skips the node. `cluster.initial_master_nodes` is written only while the data path holds no cluster state and leaves the file in the same converge once the cluster has formed, with no restart, so a second converge changes nothing; the converge stops when the node runs without its memory locked. Cloudfall's own `cloudfall` account is a superuser in the file realm, with only its bcrypt hash in `users` and its password in a `0600` file owned by `elasticsearch`; the `elastic` password is set once, as a bcrypt hash computed on the controller (D-9). Each node of the service yields the `elasticsearch` package and the generated `elasticsearch-cloudfall-password` as S-011 requirements, and `cloudfall secrets generate` also generates the `elastic` password (`ELASTIC_PASSWORD` beside `CLOUDFALL_PASSWORD` in `secrets/<environment>/services/<id>.env`); every path that runs `services.yml` decrypts both first and stops before any playbook when one is missing. More nodes, declared users, `remoteAccess` and `existingCluster` stop the converge until their slices land (#310)
