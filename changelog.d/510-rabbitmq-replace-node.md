### Added

- A lost node of a RabbitMQ service of three is replaced by naming the new server in `nodes` instead of the old one and converging (S-023): once the service's home runs, it removes the membership of every member that is neither declared nor running (`forget_cluster_node`), the new node joins on its own turn, and continuous membership reconciliation gives it a member of every quorum queue. The membership of a declared node, or of one the cluster sees running, is never removed. A declared node whose node data directory is empty while the cluster still holds its membership (same hostname, new volume) has that membership removed on a running node before it starts, and joins again in the same converge; an empty node that no other node answers for is not started, and a node that holds data is never forgotten nor reset: it rejoins the members it knows, or stops the converge at the join wait with nothing removed. A change of the node list alone no longer restarts a running node, which reads it only on its first start, so the nodes that are left keep their majority and take publishes throughout (#510)
