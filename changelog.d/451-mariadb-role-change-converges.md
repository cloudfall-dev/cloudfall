### Fixed

- A MariaDB role change now converges in either host order of the serial `services.yml` play. In a planned swap, a server declared the replica of a primary that still replicates from it turns read-only and waits (`demote`) when that primary's link names its host and port but has not connected yet (`Master_Server_Id: 0`, as after a restart), instead of refusing with `service_mariadb_replica_unattachable` while the other server waits for it. A replica whose primary holds no `cloudfall_repl` account for it yet, and whose primary's server converges later in the same run, turns read-only and answers the new `wait-primary` outcome instead of failing with MariaDB's "is not allowed to connect"; it attaches in the next converge. A primary that already converged, or whose declaration does not admit the replica, still stops the converge. The answer of a wait (`demote`, `wait-promotion`, `wait-primary`) now carries its `reason`, which says to converge again (#451)
