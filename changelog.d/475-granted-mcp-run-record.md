### Added

- Over `cloudfall mcp serve` in a project, a confirmed call of `deploy`, `rollback`, `restart`, `migrate`, `data_copy`, `domains_apply` (`yes: true`) or a `converge_*` tool (`confirm_destructive: true`) that an `OperatorPolicy` grant covers in every environment it touches now writes an agent `OperatorProposal` record to the proposal store (`record/operator/proposals/` by default): `running` before the first engine step, with the tool, its arguments and the agent's `reason`, `approval.mode: agent` with the policy and grant, and `binding.planSha256` (the sha256 of the plan the unconfirmed call answers) with the git commit and worktree digest, then `verified` or `failed` by the tool's own check (the health gate, every migrate step, the copy's receipt, `domains observe`, or an `audit` of the changed servers). The result gains `approval` with `mode`, `policy`, `grant`, `record` and `status`; on `deploy` the release approval's own `policy` is then named `release_policy`. Each gated tool takes an optional `reason` (at most 1000 characters), also a `--reason` flag on the CLI commands, where it records nothing. A confirmed call no grant covers, and every CLI command, runs as before and writes no record (#475)
