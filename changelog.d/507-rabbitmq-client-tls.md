### Added

- `services.yml` converges a RabbitMQ node with `clientAccess` (S-023): besides plain AMQP on loopback, the node takes clients over TLS alone on its server's IPv4 (5671), with its own certificate from the project CA (usage server and client, names its hostname and addresses, at `/etc/rabbitmq/cloudfall/`, the key made on the node and readable by `rabbitmq` alone), which the services converge has the node request and the project CA sign as it does for MariaDB and Elasticsearch. The node's firewall admits 5671 from `allowedSources` only (`ip saddr 10.0.0.0/24 tcp dport 5671 accept`), no RabbitMQ port is open to every address, and plain 5672 stays on loopback, so a plain connection from outside the host is refused. `audit` expects the rule. A node without `clientAccess` renders and converges as before (#507)
