### Added

- A RabbitMQ service is backed up and its restore drilled (S-023): on the service's server, `services` installs `cloudfall-rabbitmq-backup` and `cloudfall-rabbitmq-restore-check` with their systemd timers (the drill's only with `restoreCheckOnCalendar`), run as root, and `cloudfall backup run <service>` and `cloudfall backup verify <service>` run them and write their `BackupReceipt`. A backup exports the definitions of the cluster (virtual hosts, users, permissions, queues, exchanges, bindings, policies) with `rabbitmqctl export_definitions` into one file of `backup.directory`, root's and `0600` from its first byte as it holds password hashes, refuses one that does not parse or misses a declared virtual host, and then deletes the exports older than `retentionDays`, never the newest. A backup holds no message: its receipt says so in the new optional `holdsMessages` field (`false`), which only a RabbitMQ receipt carries. The drill starts a second node on the server with a node name, Erlang cookie, data directory, configuration, epmd and loopback ports of its own and no node list, imports the newest export into it at boot, compares the virtual hosts, users (and their password hashes, never printed), queues, exchanges, bindings and policies it then holds with the export, checks that the cluster does not list it, and stops it and removes its directory on every path; it fails, and says so, when there is no export, on any difference, when the server has less free memory than the scratch node's 256 MB watermark or its ports are taken, and when a process or listener of the scratch node is left (#511)
