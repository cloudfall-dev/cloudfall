### Added

- An Elasticsearch service's declared `users` converge (S-012): from the service's home server, each user gets a role of its own name limited to its `indexPatterns` (`read`: `read` and `view_index_metadata`; `write` adds `write`, `create_index` and `manage`) and a native user holding that role alone. Every path that runs `services.yml` decrypts each user's `passwordRef` first, stops before any playbook when one is missing, and stages only its bcrypt hash, computed on the controller and sent as `password_hash` (D-9); the salt is derived from the service's `cloudfall` password, so an unchanged password puts nothing and a second converge changes nothing. Users and roles Cloudfall makes carry `metadata.cloudfall_managed_by: <service id>`; a converge deletes the marked ones no longer declared and never changes or deletes an unmarked one, and refuses a declared name an unmarked user or role already holds. `inspect` reads the cluster's users and roles on the home server (`elasticsearchUsers` in the observation), and `audit` adds `elasticsearch.users[<id>]`: drift when a declared user or role is missing or a marked one is left over, with users and roles not made by Cloudfall listed as unmanaged (#311)
